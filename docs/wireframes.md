27 September 2026. These blueprints preserve the Electric A v8 information hierarchy and the complete `S-01`–`S-09` / `ST-01`–`ST-44` inventory. The final navigation-material change is a scoped structural override, not a new design direction.

## Wireframe principles

The consultation is a reading-first workspace. Content order is persistent navigation → contextual workspace action/status → current consultation view → reading controls → composer or explicit restore control. Group by task; avoid whole-app cards and nested card stacks.

On wide screens S-02 uses a sticky vertical rail containing status, active Stop and the four local views in this order: Discussion, Outcome, Sources, Usage. The main reading column shows only the selected view. A compact sticky selector replaces the rail when horizontal space is constrained. Transparent labelled top/bottom arrows sit near the viewport edges but operate only on the current visible view, disappear at its boundary and never change view. Keyboard order follows status/Stop → view controls → current content → reading arrows → composer/restore.

The persistent desktop bar exposes Discussion, Conversations, Settings and Login/Logoff; mobile keeps Login/Logoff beside a labelled hamburger. New remains above the chat and in Conversations. S-02, S-03 and S-04 extend permitted visible non-field content beneath both curved navigation ends so the scoped glass effect has real page pixels to sample. Its centre remains visually clear; native links/buttons/inputs sit outside the decorative sampling layer and remain undistorted and operable.

At 320 CSS px, global controls wrap or stack without page-level horizontal scroll; the four-view selector remains reachable, Stop and Send do not shrink away, composer controls use available width, and only semantic-table regions may scroll horizontally. Safe-area, sticky and focus offsets prevent navigation, arrows or composer from covering the focused target. No required action depends on hover.

## Shared structural contracts

**Request flow.** A fresh Send exits ST-06 into a new request-bound ST-09. Continue from ST-11 and Retry from ST-12–ST-16 retain the same request, completed results, evidence and correction states. The composer never implies that a new Send appends hidden context to an earlier request.

**Usage hierarchy.** Show totals/provenance before diagnostic detail: scope/coverage → provider/model/effort and request/participant/stage → token/cache/reasoning fields → account allowance → activity → repeat work → chronological attempts. Account allowance never shares a total with consultation usage. Missing, zero, partial, stale and unavailable each have distinct text/state, not color alone.

**Table hierarchy.** Tables remain inline with the message/outcome that introduces them. A labelled local scroll wrapper contains the semantic table; it never creates page-level horizontal scrolling. S-08 uses the same parsed rows/cells for native RTF output.

**Composer and focus.** Hide input removes only the composer region; status, Stop, view controls and reading arrows remain. Show input restores unsent draft/attachment/voice state and focuses the first useful editing/control target. Stop/failure/Retry may restore required input once, but polling cannot repeatedly reopen it or move reading focus.

**Glass structure and privacy.** The decorative sampling surface sits behind native navigation controls and has a clear centre; S-02/S-03/S-04 provide allowed content beneath the curved ends. Ordinary content, nested scroll, resize, font and visibility changes keep the last valid frame until a replacement is ready, avoiding a blank intermediate frame. Logoff, lock and disallowed rendering clear buffers synchronously and cancel/recheck deferred work. Inputs, selected option text, textarea text and cross-origin images are excluded. Unsupported rendering, reduced transparency and forced colours replace only the material with an opaque readable layer; information order/actions stay unchanged.

**Responsive priority.** At 320 px preserve, in order: identity/session control, current destination/status/Stop, selected local view, current content, reading arrows, then composer/restore. Stack Settings and Usage groups; wrap URLs/metadata; keep minimum target/focus visibility; allow horizontal scroll only within labelled table regions. At wider widths, increase content footprint beneath both navigation ends without turning the page into full-width prose or changing hierarchy.

## Notes for design brief and open questions

Electric A v8 remains the frozen approved baseline. Preserve its black-theme hierarchy, Ember message ordering, Cobalt chat/composer geometry, icon-only microphone, visible Send and selected role palette. The scoped override changes navigation sampling material, surrounding content footprint and fallback/privacy lifecycle only; final visual tuning belongs to the design brief.

Northflank/MySQL/Google/Worker deployment and its zero-active-consultation activation sequence remain operator-only and have no end-user setup, progress or success wireframe. No material wireframe gap blocks this reconciliation. Native Safari/physical-device behavior and representative-owner validation remain evidence gaps; formal release readiness remains `not_evaluated`.
