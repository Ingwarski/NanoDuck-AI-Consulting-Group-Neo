# Перевірка українського розпізнавання в Safari та Chrome

Дата спостереження: 14 вересня 2026 року. Етап: дослідна перевірка U-06, яка стала підставою для browser-native механізму. Це окрема технічна проба, не підтвердження проходження QA-U01 або AC-007.

Користувач вимагає Safari, Chrome та українську мову; відхиляє зайву складність окремого сервісу транскрипції. Після фактичної проби в обох браузерах користувач підтвердив результат відповіддю «є». Тому browser-native механізм реалізовано через власників product-idea/PRD/architecture та залежні SDD-документи. Цей запис не містить транскрипту чи приватного аудіо.

## Підтверджені спостереження

| Перевірка | Фактичний результат | Межа доказу |
|---|---|---|
| Офіційне демо Google Web Speech | У JavaScript мовного списку є `['Українська', ['uk-UA']]`; використовується `webkitSpeechRecognition`. | Перелік підтримки, не фактична транскрипція. |
| Реалізація WebKit | `WebSpeechRecognizerTask.mm` створює `SFSpeechRecognizer` для переданої мови, перевіряє доступність і вмикає локальне розпізнавання лише за його підтримки. | Поточний відкритий код WebKit; не доказ точної збірки встановленого Safari. |
| Framework Apple на macOS 26.6.2 | `supportedLocales()` містить `uk-UA`; розпізнавач створено для `uk-UA`, `isAvailable=true`, `supportsOnDeviceRecognition=false`. Англійський контрольний `en-US` має `supportsOnDeviceRecognition=true`. | Без запису, запиту дозволу чи запуску завдання. Доступність не гарантує успішну відповідь служби. |
| Chrome 153.0.0.0 на цьому Mac | Сторінка через localhost відкрилася; `secureContext=true`, доступний `SpeechRecognition`; власник підтвердив фактичний український результат. | Фактичний текст не зберігався; це не повна перевірка застосунку або мобільного Chrome. |
| Safari 26.6.2 на цьому Mac | Та сама сторінка відкрилася; `secureContext=true`, доступний `webkitSpeechRecognition`; власник підтвердив фактичний український результат. | Фактичний текст не зберігався; це не повна перевірка застосунку або мобільного Safari. |

Висновок: на перевіреному Mac є фактичне підтвердження українського результату в Safari і Chrome. Для української на Safari потрібен мережевий шлях Apple; автономну роботу не обіцяємо. На iPhone/iPad і Android проби не виконувалися; результат на Mac не поширюється автоматично на ці пристрої. Це не замінює QA-U01: він має перевірити реальний застосунок, редагування, окреме надсилання, відмову в дозволі, перехід у фон і телефонні браузери.

## Повторення й наступна перевірка

Із кореня репозиторію:

```sh
swift forge/runs/U-06/browser-speech-uk-20260914/apple-locale-check.swift
python3 -m http.server 4319 --bind 127.0.0.1 --directory forge/runs/U-06/browser-speech-uk-20260914
```

Відкрити `http://127.0.0.1:4319/` у Safari та Chrome на цьому комп’ютері. Порт належить лише тимчасовій технічній пробі; він не є новим сервісом продукту. Для перевірки на телефоні потрібна окрема доступна сторінка через HTTPS; localhost телефона не веде на цей комп’ютер.

Для release-проби в реальному застосунку власник запускає browser recognition і читає неконфіденційну українську фразу. Після Stop потрібно перевірити фактичний текст, редагування, збереження попередньої чернетки, Cancel, відмову в дозволі та припинення розпізнавання при переході у фон. Зафіксувати ОС/браузер, результат і код помилки без приватного тексту. Відсутність помилки під час установлення `lang='uk-UA'` не є успіхом. `language-not-supported`, `service-not-allowed` і `network` мають різні причини; їх не можна позначати успішною перевіркою.

Сторінка не використовує API-ключів, MediaRecorder, сховища браузера чи запитів на транскрипцію до нашого сервера. Розпізнавання запускається лише дією власника й може передавати аудіо виробнику браузера. Запис обмежений 30 секундами; скасування відновлює попередній текст. Діагностика містить лише типи подій, без транскрипту. Текст лишається в пам’яті сторінки; після перезавантаження зникає.
